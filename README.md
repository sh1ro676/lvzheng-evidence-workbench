# 律途 · 法律 AI 助手

面向律师内部研究的通用法律 Agent：DeepSeek 负责完整理解、分析和表达，北大法宝、教材与公开网页用于增强专业知识和核对出处。检索资料不是模型的知识边界，也不再要求每句话都有证据编号。

## 已实现

- 连续追问：问题规划、主回答、引用修订与四校补充共用最近对话上下文，最多 12 条消息、24000 字符；历史引用编号不沿用为本轮证据编号；新建任务清空上下文并中断旧前端请求，迟到的补充不会混入新任务或下一轮证据栏；
- 通用法律问答：支持案情梳理、概念解释、比较、归纳、推理、通俗改写等任务；没有命中外部证据时仍可回答，并自然说明事实或现行法的不确定性；
- 案件一次成稿：在同一轮中结合公开资料生成案件背景、关键行为、时间线、诉讼程序和法律分析，不再经过“占位回答＋固定模板二次重写”；
- 法律知识增强：主问答使用北大法宝在线证据、刑法教材和公开网页；本地六部法律快照不再参与主回答，只在独立文库中供用户显式检索与核验；
- 轻量引用校验：检查越界编号、已检索资料漏标和长引文匹配，不再过滤证据之外的法律知识，也不要求逐句引用；校验存在问题时仍展示完整回答并提示复核；
- 四校补充完成后合并主回答与补充部分的校验明细；任一部分未通过，整体显示“引用需复核”，补充引用与证据编号同步偏移，未取得校验结果的补充不能沿用主回答的通过状态；
- 国家法律法规数据库六部现行核心文本保留在独立文库：民法典、刑法、民事诉讼法、刑事诉讼法及两部诉讼法司法解释，共 3584 条；
- 文库支持第 N 条／中文条号精确定位，明确法律名称时只在对应法律内检索，支持一次检索多个条文；
- DeepSeek 官方 `web_search`／`web_fetch` 工具支持公开网页、最新资料和教授观点检索，后端执行搜索和正文抓取；
- 涉及法条的高校观点请求会分别检索中国政法大学、西北政法大学、北京大学法学院、清华大学法学院；每校先执行一条精准查询，未命中时才执行最多两条退化重试，首轮命中不会多搜；
- 四校查询以条文主题术语为主检索词（如“成年监护”“限制民事行为能力”“行为能力宣告”），条号与法律全称不作主检索词：论文标题和正文很少出现“第22条”，带条号只会召回百科词条、讲座预告和学者简介；重试依次覆盖学报/期刊、知网题录、前身法与学位论文；
- 候选排序按学术源加权：知网题录、维普、万方、期刊官网优先，百度百科、文库、讲座与培训页降权；首轮放宽到 10 个正文候选，避免正确的知网/期刊页被截断；
- 机构核验同时接受“北京大学法学院教授”与题录页的“机构：北京大学法学院”“作者单位”写法，不再因为缺“教授”二字丢掉知网/万方题录；学校域名、承办讲座与转载仍不算作者单位；
- 每篇正文额外抽取与所问条文相关的段落摘录（逐字、不在句中断开），模型优先据此引用，界面仍保留完整正文；
- 只采用正文明确提及所问法律、且明确体现目标学校教师任职关联的网页，每校最多一条；直接引用所问条号的论文标为 `article_text`，未逐字引用条号但主题明确的学术论文标为 `topic_paper` 和“主题相关论文网页”，不能冒充逐条释义；同条号的其他法律、无关教授简介、学校域名、转载或承办讲座均不能冒充目标证据；
- 法条／学理问题部分命中时不凑数、不启用普通全网兜底，四校均无有效正文时才转为普通全网检索；案件四校检索复用主链路搜索词，首轮覆盖评论、演讲、访谈、新书和对谈，并从真实摘要或正文中提取与目标学校教师身份相邻的人物；发现人物但尚无有效观点正文时，第二轮按“人物＋案件核心词＋学校”精确复核，每校最多搜索 2 次、第二轮最多读取 2 个候选；已有有效证据或未发现可靠人物时不追加搜索，也不启用普通全网兜底；
- 网页证据按“一手资料、官方活动页、官方网页、媒体报道、转述待核”分级，并在前端显示徽标；活动页只证明活动与身份，媒体转述和平台自媒体不能冒充教授直接原话，直接引语还会经过逐字匹配校验；
- 检索日志区分实际查询、搜索候选、人物线索、人物精确复核、正文抓取、筛选排除和最终证据，并记录每个候选的淘汰原因；
- 开启联网后，所有法律问题都会后台补充四校专业讲评，不再由模型的 `need_schools` 标记决定是否启动；命中内容必须追加到同一回答正文，不覆盖已有主回答，也不只留在检索记录；仅展示指定四校，不展开同一网页中的其他院校；
- 回答后独立检查证据编号、检索资料标注、命中学校覆盖、教材实际采用和长引文原文匹配；检索到教材却没有实质讲评与对应引用时会定向修正一次；仅长引语无法逐字匹配时就地改为间接表述并提示复核，其他引用问题才定向重生成一次；即使仍有引用问题，也保留完整回答；
- 主问答复用路由给出的网页检索词，案件法条／教材与公开网页并行检索，补充法条并行查询且保持条号顺序；普通网页首条查询获得有效证据即停止，模型配置后即使没有证据也走流式回答；
- React 工作台：问答、联网开关、真实处理阶段、检索记录、文库、引用跳转、网页外链、原文复制、元数据与校验记录；后端返回路由、检索、首字和总耗时等累计计时，便于定位性能瓶颈；
- 桌面与移动端布局，无密钥时仍可完成本地检索和原文核验。

## 启动

要求：Node.js 20+、Python 3.11+。首次使用执行：

```bash
npm install
npm run dev
```

不打开 Kimi 也可以独立运行。在 Windows 命令行中执行：

```bat
cd /d "D:\KimiData\kimi\tasks\2026-11-04\21-02-49-32ec1070\app"
npm run dev -- --host 127.0.0.1 --port 7100
```

保持命令窗口开启，然后访问 `http://localhost:7100`。关闭该窗口或在窗口中按 `Ctrl+C` 即可停止网站。开发脚本会同时启动 Vite 前端和本地 Python API，并将命令行的 host/port 参数转发给 Vite。

## 配置 DeepSeek

复制 `.env.example` 为 `.env`，填写：

```bash
DEEPSEEK_API_KEY=你的官方API密钥
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

重新执行 `npm run dev`。密钥只由本地 Python 后端读取，不进入前端代码或构建产物。没有密钥时，系统明确显示“原文检索模式”，不会模拟模型回答。

## DeepSeek 联网搜索

输入区的“联网搜索”默认开启，可在每次提问前关闭。开启后：

1. DeepSeek Chat Completions 通过 Function Calling 规划首轮查询；四校定向任务先用条文原文提炼制度术语，以术语而非条号构造查询，未命中学校再按学报、知网题录、前身法和学位论文追加变体，每校最多执行 3 次搜索；
2. 后端调用官方 `POST /v1/tools/search` 搜索，按法条相关性、论文特征、相关性和权威性排序，每轮最多抓取 5 个候选页面；
3. 后端调用官方 `POST /v1/tools/fetch` 读取正文，过滤空正文、过短正文、验证码、异常页面、错误法律或条号、无明确教师机构关联的页面；用户明确要求论文时，还会排除无论文或期刊特征的讲座、百科和课程页；
4. 网页证据与本地法条／北大法宝证据统一编号，但在界面和模型提示中明确区分资料类型，并标注一手资料、官方活动页、官方网页、媒体报道或转述待核；平台自媒体不会因宿主域名而升级；
5. 网页中的直接引语才可作为作者原话，媒体转述、搜索摘要和机构介绍不能冒充教授原话或法律原文；案件问题发现人物线索但未取得有效观点正文时，按人物进行第二轮精确检索。

联网工具与对话共用 `DEEPSEEK_API_KEY`，不需要另一把密钥。官方文档当前列明 Search、Fetch 各为每 1000 次成功请求 5 元，无结果或失败不计费，实际价格以官方页面为准。可通过 `DEEPSEEK_WEB_TIMEOUT` 和 `DEEPSEEK_WEB_CONTENT_CHARS` 调整超时与单页正文长度上限。

## 配置北大法宝 MCP

在同一 `.env` 文件中添加 Access Token 本身，不要添加 `Bearer` 前缀：

```bash
PKULAW_AUTH_TOKEN=你的AccessToken
```

重新启动开发服务。系统通过官方 Streamable HTTP 网关执行 `initialize`、`tools/list` 和 `tools/call`，同时兼容 JSON 与 SSE 响应。工具名称及参数以运行时返回的 `inputSchema` 为准，不使用硬编码的静态工具清单。

检索路由：

1. 主问答已配置 Token 时，明确法规名＋条号走 `get_law_article`；短关键词走 `search_law_articles_by_keyword`；复杂自然语言直接走 `search_law_articles`；
2. 仅当关键词检索没有可规范化证据时，自动用语义检索兜底一次；精准查询不会触发语义检索；
3. 普通查询按工具 schema 设置现行有效筛选，兼容 `type` 与 `anyOf` 类型声明；法规列表工具不用于代替法条正文；
4. “低 7 条”这类明确的数字条号错字会显示修正提示，再按“第 7 条”走精准检索，不把语义近似结果冒充指定条文；
5. 相同服务与查询在内存中缓存 15 分钟，重启后清空，不缓存完整商业库；
6. 北大法宝未配置、未命中或暂不可用时，不再回落本地快照，也不会阻止模型利用其他资料与自身法律知识作答。

`/api/providers` 仅返回是否配置、能力和策略，不返回 Token，也不会仅因打开页面而调用收费工具。配置状态不等于真实在线检索已验证。真实验证建议使用一次精准查询：`《中华人民共和国民法典》第1165条`。认证、余额、上游参数或网络错误会明确展示；模型使用未核实的一般知识时，应与检索到的具体事实和原文区分开。

## 法律数据

项目已包含入库后的条文数据和官方 DOCX 快照。需要重新从官方来源更新时：

```bash
npm run ingest
```

入库器会下载官方详情和 DOCX，验证 DOCX 条文数与官方目录一致后才写入本地文库。当前 `backend/data/documents` 只启用六部现行完整文本；`backend/data/lvzheng-archive` 完整保留从移动硬盘迁入的 2197 个资料文件，包括教授资料、原始网页、索引和历史版本，归档目录不会被检索器递归加载。迁移清单及条数见 `backend/data/manifest/e-data-migration.json`。历史时点版本选择和自动更新机制尚未纳入本原型。

## 验证

```bash
npm run test:backend
npm run test:frontend
npm run lint
npm run build
```

如本机 Chrome 位于 `C:\Program Files\Google\Chrome\Application\chrome.exe`，还可执行：

```bash
node scripts/validate-browser.mjs
```

浏览器脚本会冷启动服务，验证精确问答、文库检索、复制、弹窗与 375px 移动端布局，并在结束后关闭临时服务。

多轮追问与异步补充的浏览器回归可运行 `node scripts/validate-conversation-browser.mjs`，也可通过 `CHROME_PATH` 指定浏览器路径。该脚本使用模拟 API，不调用付费服务。

检索任务使用共享截止时间：主检索组最多 150 秒，四校并行检索组最多 100 秒，正文抓取组最多 45 秒；四校补充接口包含规划、检索、生成和重试的总预算为 150 秒。嵌套任务继承更早的截止时间，超时保留已完成分支的结果并取消排队任务，不在退出线程池时继续等待。已发出的网络请求无法强行撤回，但每次上游请求会缩短到剩余预算，预算用尽后不再发起新请求；后台未结束的任务数量也有上限。

## 精度边界

引用校验是机械性防错措施，不等于对法律结论正确性的保证。本地自然语言检索采用偏向精确率的条文检索；北大法宝在线结果仍需核对其原文、效力和适用版本。历史时点版本选择和完整法律回归题库尚未建立，正式法律意见仍需律师复核。

本项目包含运行时 API 和密钥，因此仅作为本地应用预览，不按纯静态网站发布。
